다크 값은 수치 검증(대비 계산)까지 완료, 실화면 다크 모드 스크린샷은 본 팩 범위 밖(실기기 확인 목록 참고).

원칙 3(카드와 크롬 충돌) 확인: 카드가 등장하는 4개 화면(리빌·컬렉션·상세·겹 성립) 전부에서 크롬 빨강 0~2곳으로 유지. 카드 그라디언트는 시드 기반 랜덤이라 붉은 카드가 나올 수 있으나, 크롬 빨강이 제목·CTA 위치에 고정돼 있어 카드 영역과 겹치지 않는다.

6. 덜어낸 것들 (원칙 1 "빨강은 희소해야 귀하다")

  • 선택 상태 전부 무채화 — 관심사 칩(최대 5)·성향 셀·이모지 배경. 액센트 유지 시 관심사 화면에서 빨강 최대 6곳.
  • 크롬 양보 4곳 — 맞대기 닫기·카드 상세 닫기·설정 닫기·컬렉션 설정 기어 → .tint(.primary).
  • 이스터에그 강등 — "이모지도 겹쳤어요"를 success(빨강)에서 overlapInk(와인)로. 겹침 계열로 묶여 의미도 더 정확.
  • 클립 레인 동기화 — ClipOverlapView 겹 칩을 본앱과 같은 overlap 3값으로, 비겹침 칩은 중립 표면색으로 (두 레인의 겹침 색 분화 방지, U2 제안 반영).

7. 열린 결정 — 소유자 확인 필요

  • docs 충돌: 본 트리의 미커밋 docs/design-decisions.md(Figma 세션)는 R1을 "accent=올리브 #66783A, POSTECH Red 명시 기각"으로 기록. U1 지시가 시간상 나중이자 명시적이라 방향은 U1을 따랐으나, docs 단일 진실 원칙상 병합 승인 시 R1·R8 갱신이 선행돼야 한다. 아래 갱신안 참고.
  • 선택 시맨틱: selection/onSelection은 U1이 신설한 토큰 — "선택"과 "겹침"을 분리하는 시맨틱. Figma 스타일 등록 여부는 소유자 판단.
  • 실험 브랜치의 Dynamic Type 상한·ScaledMetric·카드 칩 말줄임 수정 — §2에서 보류로 분류. 채택하려면 별도 지시 필요.
  • 병합 절차: 본 브랜치는 b248967(U2) 위에 리베이스 완료 — 승인 시 main에 fast-forward 병합 가능. U3는 U1·U2 착지 후 시작 대기 중.

8. 실기기 확인 항목

  • 다크 모드 실화면 — 수치 검증은 완료, OLED 실기기에서 #E0517F 액센트·#38121F 칩 배경의 체감 확인.
  • iOS 26 Liquid Glass 위 CTA — 시뮬레이터 확인 완료, 실기기 글라스 블러 위 채도 체감(원칙 4)은 실기기에서.
  • U2 겹 융합 연출과의 색 조합 — 링(accent)이 이제 레드 — 실기기 모션에서 과하지 않은지.
