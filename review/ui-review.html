9-1. 다크 모드 — 코드 감사: 리터럴 색상 0건, 실화면 재검 10화면: 이슈 0건

DS.Palette.* 밖에서 직접 색을 쓰는 곳은 CardKit뿐이었고 전부 의도된 예외다 — CardView/GyeopMomentView의 .white는 카드 콘텐츠용 고정 흰 글자(카드 배경이 자체적으로 4.5:1 대비를 보장하는 생성 그라디언트라 시스템 배경과 무관, CLAUDE.md가 CardKit에 허용한 커스텀 비주얼 예외), GooBlobs의 .black은 alphaThreshold 마스크용 불투명도 트릭이라 색으로 렌더링되지 않는다. 나머지 전부 DS.Palette.* 아니면 시스템 시맨틱(.primary·.secondary·systemGroupedBackground)이라 다크 대응이 자동이다.

실화면 검증에서 실제로 걸린 것은 코드가 아니라 테스트 하네스였다: UI 테스트 런치 인자 -UIUserInterfaceStyle Dark는 최신 iOS 시뮬레이터에서 더 이상 앱 외관을 바꾸지 않는 no-op임을 확인 — 처음 캡처한 "다크" 스크린샷 10장이 실제로는 라이트였다. xcrun simctl ui <device> appearance dark로 시뮬레이터 자체를 다크로 전환한 뒤 재캡처해서 진짜 다크 화면 10장을 확보했고 (아래 링크), 재발 방지로 UITests/ScreenshotAndAccessibilityUITests.swift의 testFullFlowDarkMode에 이 절차를 주석으로 남겼다. 진짜 다크 화면 10장 전부 — 액센트·overlap 3값·글라스·칩 대비 — 육안 이슈 없음.

9-2. Dynamic Type 최대(AX5)·최소(XS) — 6건 수정

파일문제수정
CardKit/CardView.swift 고정 .aspectRatio(0.7, contentMode: .fit)가 AX5에서 자라는 콘텐츠(닉네임·태그라인·칩)를 clipShape로 잘라냄 — 카드를 쓰는 모든 화면(리빌·상세·컬렉션·교환·클립 3곳)에 영향 dynamicTypeSize.isAccessibilitySize일 때 비율 제약을 풀어 세로로 자라게 함
ExchangeView.progress() Spacer 2개로 감싼 고정 레이아웃 — AX5에서 제목+캡션이 화면을 넘치면 잘림. 같은 화면의 completed/failed는 이미 스크롤 패턴이었는데 이 단계만 빠짐 ScrollView로 통일
Onboarding/StyleStepView.swift 4셀 Grid가 스크롤 없는 VStack에 있어 AX5에서 하단 셀이 화면 밖으로 밀림 InterestsStepView와 같은 ScrollView+safeAreaInset 패턴 적용
Onboarding/InterestsStepView.swift 칩 라벨 .lineLimit(1)로 긴 관심사명이 AX5에서 말줄임 .lineLimit(2) + .minimumScaleFactor(0.8)
Welcome/WelcomeView.swift SIWA 버튼 .frame(height: 50) 고정 — AX5에서 내부 라벨이 잘릴 위험 .frame(minHeight: DS.minTapTarget)로 완화
ClipBumpView.swift / ClipFailureView.swift ExchangeView와 같은 결함 — 특히 ClipFailureView는 재시도 버튼이 Spacer 사이에 있어 AX5에서 화면 밖으로 밀릴 수 있었음 ScrollView + safeAreaInset(edge: .bottom)로 버튼 항상 도달 가능하게
ClipKeepView.swift / ClipReceptionView.swift GroupBox 행 닉네임+캡션 HStack이 AX5에서 한 줄을 두고 경쟁 ViewThatFits로 안 맞으면 세로 스택으로 전환

XS(최소)는 코드 변경 없음 — 기존 시스템 텍스트 스타일 매핑만으로 레이아웃이 여유롭게 맞는 것을 스크린샷으로 확인. XS 스크린샷: review/assets/postech/xs/xs-1-onboarding-interests.png ~ xs-10-settings.png.

9-3. 빈 상태 — 2건 수정

  • Onboarding/ProfileStepView.swift — 이모지 검색 결과가 0건일 때 그리드 자리가 조용히 비어있던 것을 "일치하는 이모지가 없어요" 안내로 대체.
  • AppClipKit/ClipOverlapView.swift — 겹친 관심사·상대만의 관심사가 둘 다 0개인 극단 케이스(양쪽 다 관심사 미입력)에서 칩 영역이 빈 채로 남던 것을 "이번엔 등록된 관심사가 없었어요" 한 줄로 대체. 컬렉션 빈 상태(점선 슬롯 + "다음 만남이 여기에")는 기존 구현 그대로 — navigation-map.md §2와 정합 확인.

9-4. VoiceOver — 4건 수정

  • Collection/CardDetailView.swift — .accessibilityElement(children: .combine) + 커스텀 .accessibilityLabel이 하위 Text들의 결합 라벨을 덮어써서, 화면 맨 아래 "다음에 만나면 여기서 시작하세요" 팁을 VoiceOver 사용자만 못 듣던 문제 — 라벨 문자열에 팁을 합쳐 넣음.
  • AppClipKit/ClipOverlapView.swift — 같은 패턴의 결함 2건: 대화 시작 문구(talkLine)와 "상대만 가진 관심사"(흐린 칩, 시각적으로는 보이지만 라벨에서 빠짐)가 커스텀 라벨에 없었음 — 둘 다 라벨에 포함.
  • 나머지 19개 뷰는 이모지·아이콘·카드 등 비텍스트 요소에 accessibilityLabel 누락 없음, 44pt 미만 탭 타깃 없음, 합성 뷰의 .combine 사용이 일관됨을 확인 (Explore 에이전트 전수 정독 + 수동 재확인).

9-5. 햅틱 상수 — 실기기 피드백 반영: 블로킹, 코드 변경 없음

docs/device-required.md의 "CoreHaptics 교환 햅틱" 항목은 "감각 튜닝은 D1 결정 대기, 실기기 체감 확인 필요" 상태 그대로다 — 즉 반영할 실기기 피드백 자체가 아직 존재하지 않는다. U3는 실기기가 없어 이 항목을 블로킹으로 보고하고 코드를 건드리지 않았다 (임의로 값을 지어내면 다음 실기기 세션에서 다시 튜닝해야 하는 이중 작업이 된다). 튜닝 표면은 이미 U2가 GyeopKit/HapticFeedback.swift의 HapticTuning enum(강도·날카로움·더블탭 간격 8개 상수)으로 분리해뒀다 — 실기기 세션에서는 이 상수들만 조정하면 된다.
