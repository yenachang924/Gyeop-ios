1. 클립 레인 — 화면 전수 (배선표 §1 순서)

1 · clip — 카드 수신 R2
  • 구 단일 온보딩 화면을 배선표 9단계 레인으로 재구성 — 첫 화면이 수신으로 분리
  • 인보케이션 URL(?t=토큰&n=닉네임)의 발신자 닉네임이 헤드라인·카드 자리에 반영
  • 「내 카드 만들기」 → 온보딩, 「카드는 어떻게 만들어지나요?」 → 설명 시트
1b · 설명 시트 (§1-1 변형) R2
  • 미디엄 디텐트 시트 — 닫으면 clip으로 (배선표: 시트는 Figma 오버레이 대응)
  • 카드 생성 원리 한 문단: 입력=시드, 같은 입력=같은 카드, 사진·계정 불필요
  • 프로토타입은 이 버튼이 interests로 직행 — 배선표 확정안(시트)을 따름
2 · interests — 관심사 (본앱 뷰 소스 공유) R3
  • 138행 큐레이션 카탈로그(이모지+이름 칩), 최대 5개 — 초과 선택은 비활성
  • 고르는 순간 상단 카드 프리뷰가 물든다 (실시간 시드 재계산)
  • 0개면 「다음 · 0/5」 비활성 · 뒤로 스와이프 → clip (R4, §1-2)
3 · vibe — 여가 성향 R4
  • 2×2(정적/동적 × 실내/실외) 4택1 — 선택이 화면에 강조로 남는다
  • 미선택이면 하단 「다음」 비활성 (배선표 §1-3 정렬 — 이번 수정)
  • 선택 셀에 예시 카피(보드게임·독서 …) — 프로토타입 확정 카피
4 · intro — 닉네임·한 줄·이모지 R3
  • 전부 선택사항 — 다 비워도 「카드 완성」 진행 (§1-4)
  • 이모지는 1차 16개 노출 + 키워드 검색으로 138행 전체 접근
  • 「카드 완성」 → 클립은 리빌 없이 곧장 card 단계로 (본앱과의 유일한 차이)
5 · card — 이게 나예요 R2
  • 입력 시드로 결정론 렌더된 내 카드 (CardKit 셰이더)
  • 「지수님과 맞대기」 — 발신자 닉네임이 버튼에 실린다
  • 여기까지 설치 유도 UI 없음 — UI 테스트가 매 화면 단언
6 · bump — 아이폰을 서로 가까이 R2
  • 실기기: MPC 자동 트리거 / 시뮬레이터: Mock 스크립트 약 3초 (배선표 실앱 열)
  • 시스템 ProgressView — 커스텀 비주얼은 카드만 허용(가드레일)이라 오브 애니메이션 없음
  • 실패 시 failed 화면(중립 톤) → 「다시 시도」로 bump 재진입
7 · overlap — 겹 결과 (캡처는 겹침 0개 변형, §2)
  • 겹치면 강조 칩 + "○○가 겹쳐요", 0개면 "겹치는 관심사는 없지만" — 이 캡처는 0개 변형(테스트 선택 달리기·자전거 ↔ 상대 클라이밍·보드게임·커피)
  • 상대만의 관심사는 흐림 칩으로 — 서로 없는 것도 대화 소재라는 카피
  • 상대 카드 렌더 + 같은 이모지면 이스터에그 한 줄 (R3)
8 · keep — 보관·전환 제안 R4
  • 레인에서 유일하게 설치를 언급하는 화면 — 이전 화면 노출 금지를 UI 테스트가 단언
  • 「전체 앱 받기」 → SKOverlay → 닫힘(완료) 시 done (이번 수정, §1-8) · 「나중에 할게요」 → 거절 비용 0
  • 클립 30일 보존 고지 (ClipRetentionPolicy) + 겹친 관심사 개수 표기(캡처는 0개 변형) — App Group 저장·본앱 마이그레이션 우편함
9 · done — 나의 겹 R2
  • 내 카드 + 오늘의 겹 1장 — 설치 없이도 가치가 온전히 성립하는 종착점
  • 실앱 전환 시 이 기록은 App Group 우편함으로 본앱 컬렉션에 병합
  • 배선표 §1-9: 클립은 여기 머무름 (처음부터는 프로토타입 전용)
변형 · failed — 교환 실패 R2
  • 중립 톤 실패 문구 (실패는 거절이 아니다 — 경고색 금지 원칙)
  • 「다시 시도」 → bump 재진입, 성공 시 overlap까지 회복 (단위 테스트)
  • 실패 화면에도 설치 유도 없음 — UI 테스트 단언

3. 프로토타입과 달라진 점

  • reception의 발신자 카드 = GroupBox 자리 표시 (토큰→카드 조회 미구현) 프로토타입은 지수의 실제 카드(미니)를 렌더하지만, 인보케이션 URL에는 토큰(t)·닉네임(n)만 있고 카드 데이터는 교환에서야 도착한다. 토큰→카드 조회(서버/캐시)가 생기면 CardView로 교체 — 코드 주석으로 명시해 둠.
  • 「카드는 어떻게 만들어지나요?」 = 설명 시트 프로토타입은 interests로 직행하지만, 배선표 §1-1 확정안(설명 시트 → 닫으면 clip)을 따랐다.
  • 온보딩 단계 표시: stepdots → 내비게이션 타이틀 "1/3 · 2/3 · 3/3" 시스템 컴포넌트 우선 원칙. 프로토타입의 점 3개 인디케이터는 도입하지 않음.
  • vibe·intro 상단 카드 프리뷰 없음 프로토타입은 세 단계 모두 상단에 프리뷰 카드가 있지만, 코드는 interests에만 실시간 프리뷰가 있다 (R3 범위). 2·3단계 프리뷰 확장은 소유자 판단 대기.
  • bump 비주얼: 오브 애니메이션("겹!") → 시스템 ProgressView 커스텀 비주얼 허용 범위가 카드뿐이라는 가드레일에 따름. 햅틱은 실기기 전용.
  • bump 트리거: 프로토타입 수동 버튼 → 자동 (MPC/Mock) 배선표 §1-6 실앱 열("MPC 자동 트리거") 그대로 — card의 「맞대기」 탭 후 자동 진행.
  • keep의 SKOverlay는 시뮬레이터에서 실제 App Store 카드가 뜨지 않음 미배포 앱이라 실기기+배포 후에만 실동작 확인 가능. 완료 시 done 전환은 델리게이트 경로로 구현·단위 테스트만 완료.
  • App Clip 필(상단 "설치 없이 실행 중")은 OS가 그리는 요소 — 코드/스크린샷에는 없음.

4. 실기기 확인 필요 (시뮬레이터 검증 불가)

  • MPC 맞대기 왕복 (핵심) — 시뮬레이터는 MockExchangeSession. 실기기 2대: 발견→연결→전송 3초 이내, 양쪽 컬렉션 동시 기록, 타임아웃·peerLost·재시도 엣지. 로컬 네트워크 권한 프롬프트 동작 포함.
  • 교환 햅틱 — peerFound·connected·completed·failed 패턴 구분 체감 (시뮬레이터 no-op). 감각 튜닝 별도.
  • SKOverlay 실동작 — keep 「전체 앱 받기」 → App Store 카드 표시·닫힘 → done 전환 (배포 후에만).
  • App Group 마이그레이션 — 클립 겹 기록이 본앱 첫 부트스트랩에서 병합되는지 교차 프로세스 확인.
  • 클립 실도메인 인보케이션 — AASA 검증·태그/QR 자동 실행은 도메인 확정 후 (제출 리스크 목록 유지).
  • 전체 목록·통합 실행 계획(2대·약 2시간)은 docs/device-required.md 참조.

이 문서는 통합 세션이 생성했다. 스크린샷은 UI 테스트 첨부(xcresult) 자동 추출 — 재촬영: Gyeop 스킴 ScreenshotAndAccessibilityUITests, GyeopClip 스킴 ClipLaneUITests. 소유자 승인 전 추가 구현 없음.
