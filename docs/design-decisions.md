### F44 — 로그인 게이트가 건너뛰어지던 버그 (2026-08-09)

**증상:** 앱을 삭제하고 다시 설치해도 웰컴("겹") 화면이 뜨지 않고 바로 앱 안으로 들어갔다.

**원인 두 가지**

1. **Keychain은 앱 삭제로 지워지지 않는다** (iOS 설계). SwiftData·UserDefaults는 앱과 함께
   사라지지만 Keychain의 SIWA 토큰은 기기에 남는다 → `signedIn`이 계속 참이라 게이트를 건너뛴다.
2. `AppModel.live()`의 **SwiftData 실패 폴백 경로에 `requiresSignIn`이 빠져 있었다** —
   기본값 `false`라 그 경로에서는 로그인 게이트 자체가 사라진다.

**해결**

- `bootstrap()` 시작에서 `clearTokenIfFreshInstall()` — UserDefaults 플래그가 없으면
  "재설치 후 첫 실행"이므로 토큰을 비운다. 앱을 지웠다 깔면 새로 로그인하는 게 사용자에게도
  자연스러운 동작이다.
- 폴백 경로에도 `requiresSignIn: true` 명시.

**테스트 시 참고:** 앱 삭제만으로 초기화가 되지 않던 이유가 이것이다. 이제는 삭제 후 재설치로
웰컴 화면부터 확인할 수 있다.

### F45 — 이모지 칸 전면 재구성 (2026-08-09)

### F46 — 이모지가 칸 밖으로 날아다니던 문제 (2026-08-09)

**증상:** 이모지를 고를 때마다 이모지들이 격자를 벗어나 날아다니고 전환이 끊겼다.

**원인:** `Form` **전체**에 `.animation(_:value: incomplete)`를 걸어둔 것.
첫 이모지를 고르는 순간 `incomplete`가 `true → false`로 뒤집히고, 그 트랜잭션이
**폼 안의 모든 행에 전파**되어 이모지 셀 137개가 한꺼번에 위치 애니메이션을 탔다.
(`.animation(_:value:)`는 그 뷰의 **하위 전체**에 걸린다 — 컨테이너에 붙이면 안 된다.)

**규칙 (앞으로 지킬 것):** 애니메이션은 **실제로 변하는 뷰에만** 붙인다. 컨테이너
(`Form`·`List`·`ScrollView`·`VStack`)에 `.animation(_:value:)`를 거는 것은 금지.

**해결**

- Form 레벨 애니메이션 제거
- 셀의 애니메이션 트리거를 `draft.emoji` → **`isSelected`(자기 칸의 선택 여부)** 로 변경.
  이제 값이 바뀐 두 칸만 반응하고 나머지 135개는 미동도 없다
- 카테고리 전환은 `.animation(nil, value: category)`로 **즉시** — 위치를 보간하면
  이전 묶음의 이모지가 새 자리로 날아가는 것처럼 보인다. 이모지는 사전에 이미 꽂혀
  있던 것처럼 제자리에 있어야 한다는 소유자 기준
- 선택 스케일 1.08 → 1.06 (칸 안에 머문다)
- 같은 부류의 실수였던 `WelcomeView`의 화면 전체 `.animation(value: failed)`도
  실패 문구 하나로 국소화

  토큰이라 남긴다 (시스템 컨트롤은 `.disabled()`가 알아서 흐려진다)

### 7차 — 성능 병목 + 전환 부드러움 (2026-08-09)

#### F49 — 매 프레임 재계산 병목 두 곳

`CardVisual` 생성은 sha256 기반 PRNG + **색마다 대비 보정 루프**(`pow` 반복)라 결코
가볍지 않다. 그런데 두 곳에서 프레임마다 다시 만들고 있었다.

| 위치 | 문제 | 해결 |
|---|---|---|
| `CardView` | 메시 색을 `body` 안, 그것도 `KeyframeAnimator` **콘텐츠 클로저** 안에서 만들었다. 이 클로저는 stir 애니메이션 동안 매 프레임 호출된다 | `init`에서 한 번 계산해 `meshColors`로 보관 |
| 온보딩 2/3 | 슬라이더를 끄는 매 프레임 `blendedColors`가 **4개의 `CardVisual`**(sha256 4회)을 새로 만들었다 | `CardPreview.QuadrantPalette`로 분리 — 4분면 팔레트는 관심사가 바뀔 때만 만들고, 드래그 중에는 색 보간만 |

추가로 `EmojiCatalog.icons(in:)`이 호출마다 137개를 훑던 것을 카테고리별 사전으로 미리 묶었다.

#### F50 — 화면 전환 부드러움

- `RootView`: 단계(`loading·signIn·onboarding·home`) 전환이 뚝 갈렸다 → **크로스페이드**
  (`.transition(.opacity)` + `settle`). 자식이 항상 하나뿐이라 F46 금지 규칙의 안전한 예외
- **계정 삭제 전환**: 시트 닫힘과 루트 교체가 **동시에** 일어나 거칠었다. `AppModel.deleteAccount()`가
  더 이상 단계를 바꾸지 않게 하고(`returnToEntry()`로 분리), 시트를 닫은 뒤 0.32초 기다렸다가
  루트를 넘긴다. 삭제 실패는 시트가 살아 있는 동안 알려야 하므로 삭제를 먼저 시도한다

#### F51 — 웰컴 배경

앱 아이콘의 **겹친 두 원을 세로로** 세워 깔았다 — "겹!" 순간 연출(R7)과 같은 버티컬 축이라
브랜드 언어가 이어지고, 워드마크가 두 원이 겹치는 자리에 선다. 위 = 브랜드 레드, 아래 =
골드·올리브. 깊은 블러 + 낮은 불투명도(라이트 16% / 다크 30%)로 텍스트 대비를 지킨다.

### 8차 — 액센트 슬라이더 + 유동 배경 (2026-08-10)

#### F52 — 성향 슬라이더 트랙을 브랜드 색으로

채워진 구간이 `.tertiary`(무채)라 "지금 어디를 잡고 있는지"가 약하게 읽혔다. 채움만
**POSTECH Red(`accent`)**로 올린다. 빈 트랙은 `.quaternary`, 손잡이는 시스템 배경색 그대로 —
액센트가 한 화면에 넘치지 않는다(액센트 3곳 규칙: 이 화면에서 액센트는 슬라이더 채움 2개와
「다음」 버튼뿐이고, 슬라이더 채움은 같은 컨트롤의 반복이라 1곳으로 센다).

#### F53 — 웰컴 배경: 겹친 두 원 → 유동 구형 글라스

F51의 배경은 **정지 화면**이었다. 소유자 지시(2026-08-10): "겹 색깔 은은한 거, 구형 글라스
배경 일렁이는 형태. 구형이 뚜렷하진 않아도. 레퍼런스는 애플 유동 배경화면."

| 축 | F51 | F53 |
|---|---|---|
| 형태 | 선형 그라디언트 원 + 블러 60 | **방사 그라디언트 구**(중심이 위로 치우친 광원) + 블러 34 |
| 가장자리 | 블러로 뭉갠 원 테두리가 남았다 | 알파가 반지름 끝에서 0이 되어 **테두리 자체가 없다** — "뚜렷하지 않은 구" |
| 유리감 | 없음 | 각 구 위쪽에 흰 반사(sheen) 한 겹 — 다크에서 유리처럼 빛나고 라이트에서는 광택으로만 읽힌다 |
| 움직임 | 정지 | 두 구가 **서로 다른 주기**(13s·17s)로 오르내리며 부풀었다 줄어든다. 주기가 어긋나 패턴이 반복으로 읽히지 않는다 |
| 겹치는 자리 | 두 색이 그냥 겹침 | 만나는 띠에 **`overlapInk`(와인) 구**를 한 겹 더 — 겹 칩과 같은 색이다. 자체 주기 21s |

투명도 상한은 F51보다 소폭 올렸다(라이트 20% / 다크 34%). 방사 페이드로 평균 밀도가
떨어져 같은 값이면 F51보다 더 옅게 보이기 때문이다. **이 값이 대비 상한이다** — 소제(골드
17pt)가 골드 구의 꼬리 위에 앉으므로 더 올리면 4.5:1이 깨진다. 두 구의 **핵은 텍스트 스택
위아래**에 있고 중앙에는 꼬리만 닿는 배치가 이 여유를 만든다.

성능: 상시 반복 애니메이션이라 값이 아니라 **변환만** 움직인다(offset·scale). 색 계산은
프레임마다 하지 않는다(F49 교훈). Reduce Motion에서는 정지 상태로 고정한다.

### 9차 — 스타일 스텝 축 슬라이더 트랙: Liquid Glass + 전체 브랜드 색 (2026-08-10)

#### F54 — StyleStepView `AxisSlider` 트랙

소유자 지시(2026-08-10): "바에 리퀴드 글라스 적용, 바 색깔은 메인컬러로." 적용 범위는
**StyleStepView 하나뿐** — 다른 화면의 스크롤·슬라이더는 대상이 아니다.

F52는 트랙을 빈 구간(`.quaternary`)과 채워진 구간(`accent`)으로 나눠 "액센트가 화면에
넘치지 않게" 절제했다. 이번 지시는 그 절제를 **이 화면에 한해** 뒤집는다 — 트랙 전체를
하나의 액센트 틴트 Liquid Glass 캡슐로 바꾸고, 빈/채움 구분은 없앤다. 값 위치는 여전히
손잡이(원)로만 읽는다 — 손잡이는 기존대로 시스템 배경색 유지(트랙과 대비되어야 보인다).

```swift
if #available(iOS 26.0, *) {
    Capsule()
        .fill(.clear)
        .frame(height: Layout.track)
        .glassEffect(.regular.tint(DS.Palette.accent), in: Capsule())
} else {
    Capsule()
        .fill(DS.Palette.accent)
        .frame(height: Layout.track)
}
```

iOS 26 미만(배포 타깃 18)은 글라스 재질 자체가 없으므로 단색 액센트로 폴백한다 — F20의
`dsProminentButton`/`dsGlassButton`과 같은 가용성 분기 관습을 그대로 따른다.

이 화면 밖(컬렉션 스크롤 등 네이티브 스크롤 인디케이터)은 이번 지시 대상이 아니다 —
착오로 번지지 않도록 여기 명시해 둔다.

#### F55 — 소유자 로컬 편집 회수 (2026-08-10)

소유자 Mac에 커밋되지 않은 채 남아 있던 편집 둘을 F54 브랜치 위로 옮겼다. 로컬 베이스가

**의도한 두 변경만** 발췌해 적용했다(스태시 통째 병합 아님).

| 변경 | 내용 | 판단 |
|---|---|---|
| 안내 카피 | "두 축을 움직이면 성향이 잡혀요" → **"바를 움직여서 당신의 성향에 맞춰보세요"** | 소유자 작성 카피 그대로. em-dash 없음(카피 규칙 준수) |

#### F56 — 손잡이를 실제 알약으로 (2026-08-10)

F55의 `Capsule()`은 프레임이 `thumb × thumb`(28×28) **정사각**이라 렌더 결과가 Circle과
똑같았다 — 도형만 바꾸고 비율을 안 바꾸면 모양이 변하지 않는다. 소유자 지시로 너비를 분리했다.

| 상수 | 값 | 근거 |
|---|---|---|
| `thumbWidth` | **44** | 알약으로 읽히는 최소 비율(1.57:1). 동시에 **HIG 최소 터치 타깃 44pt**를 가로축에서 충족한다 — 이전 28pt는 CLAUDE.md의 44pt 원칙에 미달이었다 |
| `thumbHeight` | 28 | 기존 값 유지 — 트랙(6pt) 대비 두께 위계를 그대로 둔다 |

이동 거리 계산도 `geo.size.width - thumbWidth`로 바꿨다. 손잡이 너비가 커졌는데 이걸 안 고치면
값이 1일 때 손잡이가 트랙 오른쪽으로 넘친다. 검증: `clamped=0` → `[0, 44]`,
`clamped=1` → `[width-44, width]`.

⚠️ 세로 터치 타깃은 여전히 28pt다(가로만 44 충족). 완전히 지키려면 `contentShape`으로 히트
영역만 44로 넓히면 된다 — 시각은 그대로. 두 슬라이더 행 간격이 16pt라 위아래 8pt씩 넓혀도
서로 겹치지 않는다. **적용 여부는 소유자 판단 대기** (F48의 "트랙 탭은 무시" 원칙은 유지됨 —
손잡이를 잡기 쉬워질 뿐 트랙 탭 동작이 생기는 게 아니다).

⚠️ 스태시 기준 코드에 채움 트랙이 `.fill(.tertiary)`로 보였던 것은 **F52 이전 베이스라서**지
소유자가 F52를 되돌린 게 아니다 — 되돌림으로 오독하지 말 것.
