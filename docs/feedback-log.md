# 겹(Gyeop) — 피드백 로그

피드백을 받은 순서대로 기록하고, 각 항목이 어디에 반영됐는지 추적한다. **원칙: 피드백은 기록 → 문서 반영 → 세션 동기화 순서로만 코드에 닿는다.**

## 고정 원칙 (모든 피드백의 공통 기준)

1. **사용자 경험이 우선이다** — 기술·일정·아이디어 애착보다 UX가 먼저. 모든 결정의 1순위 판단 기준
2. **아카데미 러너는 사용자가 아니라 피드백 그룹이다** — 방금 UX 챌린지를 끝낸 가장 가까운 리뷰어들
3. App Clip으로 받는 쪽 비용을 0으로 — 설치 제안은 가치를 다 얻은 뒤에만

## 1차 — 재성 (파운데이션 담당 멘토) · 2026-08

### 요지

- 사용자 경험이 우선. 틀을 만들어보자 — **처음 만나는 사람들끼리**
- 아카데미 러너 대상의 구조적 문제: ① 개인정보·보안 전제가 무겁다 ② 멘토·운영 환경이 기수마다 바뀌어 영속성 보장이 없다 ③ 내가 아카데미 밖에 있고, 그 생태계 이해도는 러너가 더 높다 ④ 시연하는 순간 아이디어를 빼앗길 위험 — 그들이 만들면 되는 구조
- 그럼에도: **첫 만남의 아이스브레이킹 + 아이덴티티 카드 교환** 장치로 피벗하면 좋겠다. App Clip 활용, 설치 요청 시점이 관건
- 프로토타입을 최대한 빠르게 → 러너들을 멘토로 활용 → 개발 착수

### 반영 내역

| 피드백 | 반영 위치 |
|---|---|
| 대상 피벗 (러너 → 범용 첫 만남) | `README.md` 전면 개정, `gyeop-spec.md` 피벗 공지, `implementation-scope.md` v2 |
| App Clip + 설치 시점 고민 | 신규 코어 기능 ③ (스코프 §1), 프로토타입 8번 화면 = "설치 제안은 교환 후" |

| 아카데미 종속 기능 제거 | 여가 신호→모임 모드(후순위), 이메일 인증 삭제, 룰렛·스팟·D-day 백로그 |

## 2차 예정 — 존 (보안에 철저)

**목적:** 보안·개인정보 관점의 구멍을 출시 전에 찾는다. 존이 잘 볼 부분을 미리 준비해서, 일반론이 아니라 **구체 설계에 대한 답**을 받아온다.

### 들고 갈 질문 (보안 중심)

1. **P2P 페이로드** — 맞대기 교환은 `MCSession` encryption `.required`로 갈 계획. 근거리 도청·중간자 관점에서 충분한가? 카드에 넣으면 안 되는 필드가 있는가?
2. **무계정 App Clip** — 수집 항목을 닉네임·관심사·이모지로 최소화했다. 무계정 상태의 데이터가 기기 밖으로 나가지 않게 하는 설계(클립은 로컬 온리)가 맞는 방향인가?
3. **계정 삭제의 한계** — 내 계정을 지워도 **이미 상대에게 전달된 내 카드**는 상대 기기에 남는다. 이걸 어떻게 고지/정책화해야 하나? (전파 삭제는 기술적으로 불가 — 명함과 같은 논리로 갈 생각)
4. **가짜 QR/링크** — 어소시에이티드 도메인 검증으로 위조 클립은 막히지만, 악성 QR이 다른 앱/사이트로 유도하는 시나리오에 대한 UX적 방어가 필요한가?
5. **만남 기록의 민감성** — 겹 기록은 시각+상대만 저장, 위치는 v0.1에서 아예 수집 안 함. 시간 정보만으로도 문제가 될 수 있는 케이스가 있나?
6. **30일 클립 데이터 정책** — 클립→풀앱 마이그레이션(App Group) 시 사용자 고지가 필요한 수준인가?
7. **App Privacy 라벨** — 심사 시 데이터 수집 항목 신고에서 흔히 걸리는 함정이 있나?

### 답변 후 할 일

- 답변을 이 문서에 기록 → 반영 항목을 `gyeop-spec.md`(정책)·정렬 세션(코드)으로 라우팅
- 개인정보 처리방침 초안에 반영 (외부 TestFlight·심사 필수물)
