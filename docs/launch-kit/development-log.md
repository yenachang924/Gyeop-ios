# 겹 개발 기록 | 가설을 화면과 테스트로 바꾼 과정

## 1. 제품 가설

앱의 목적은 온라인 관계를 늘리는 것이 아니라, 오프라인에서 대화를 시작할 계기를 만드는 것이었다. 그래서 공개 피드, 검색, 풀 채팅을 범위에서 제외하고 카드와 근접 교환에 집중했다.

## 2. 디자인 의사결정 기록

| 단계 | 가설 | 관찰 | 결정 |
|---|---|---|---|
| 카드 생성 | 다양한 색을 많이 쓰면 각자의 카드가 더 특별해진다 | 카드마다 언어가 달라지고 정보가 묻혔다 | 4색 인접 hue와 5×5 메시로 규칙을 줄였다 |
| 카드 텍스트 | 흰 텍스트가 유리 카드에 어울린다 | 밝은 파스텔에서 읽히지 않았다 | 딥 잉크와 4.5:1 자동 대비 보정을 적용했다 |
| 카드 뒷면 | 이모지와 유리 버블을 크게 두면 관심사가 더 눈에 띈다 | 카드 표면이 분절되고 렌더 비용도 증가했다 | 별도 원형 레이어를 제거하고 MBTI·관심사 중심 포스터 구조로 복귀했다 |
| 카드 플립 | 양면을 항상 두면 전환이 단순하다 | 홈에서 정지 상태도 무거웠다 | 플립 순간에만 양면을 렌더한다 |
| 이모지 입력 | 일반 텍스트 필드로 충분하다 | 대표 이모지 입력이 번거로웠다 | 시스템 이모지 키보드 전용 필드를 만들고 선택 후 자동으로 닫았다 |

## 3. 품질 기록

- Swift 6 strict concurrency를 유지했다.
- 패키지 단위 Swift Testing 72개로 시드 결정성, 대비, 저장, 교환 상태 전이, 멱등성을 검증했다.
- XCUITest로 온보딩부터 Mock 교환, 컬렉션, 카드 앞뒤, 설정까지 흐름을 자동화했다.
- 결과 화면은 xcresult attachment에서 추출해 라이트, 다크, XS, AX5 크기로 직접 확인했다.
- 실기기 두 대로 근접 교환, 실패와 재시도, 햅틱, 24시간 중복 규칙을 확인했다.

## 5. 포트폴리오에서 강조할 역량

1. **문제의 범위를 줄이는 판단**: 채팅이나 피드가 아니라 오프라인 근접 교환에 집중했다.
2. **디자인을 규칙으로 전환하는 구현력**: 시드, 색상 보간, 대비 기준, 레이아웃을 코드 계약과 테스트로 남겼다.
3. **실패를 되돌리는 품질 감각**: 화려한 유리 레이어가 실제 카드 경험을 해친다는 것을 확인하고 제거했다.
4. **출시까지 가져가는 실행력**: 실기기 검증, 스크린샷 자동화, Archive, TestFlight 업로드까지 완료했다.

## 6. 성과를 기록할 때의 원칙

아래 수치는 실제 TestFlight 기간이 지난 뒤에만 추가한다.

- 설치 수, 활성 테스터 수
- 온보딩 완료율
- 카드 생성 완료율
- 2대 근접 교환 성공률
- 받은 카드 삭제, 재시도 등 이탈 지점
- 자유 응답에서 반복되는 불편과 요청

목표치나 개인적 기대를 성과처럼 쓰지 않는다. 대신 어떤 피드백으로 무엇을 바꿨는지 전후 맥락을 기록한다.
