# 겹(Gyeop) — 재성 피드백 반영: Orca 정렬 세션 프롬프트 (상세판)

기존 Orca 산출물(피벗 이전 기획 기준)을 **재성 1차 피드백이 반영된 현재 기획으로 정렬**하기 위한 세션별 프롬프트. 복사해서 그대로 사용한다.

**이번 정렬의 계약 4조:**
1. **재성 피드백만 반영한다.** 존(보안) 피드백은 TestFlight 이후로 보류 — 이번 스프린트에서 보안 구조 변경 금지
2. **디자인 시각 이탈 금지.** 기존 토큰·컴포넌트·비주얼 방향(시스템 컴포넌트 + 리퀴드 글라스 + 카드 그라디언트)을 유지한다. 허용되는 것은 **내용 구성의 변화**(화면 내 섹션 추가·제거·순서, 카피 교체)뿐. 새 색·새 폰트·새 코너값·새 비주얼 스타일 도입 금지
3. **HTML 게이트.** `docs/gyeop-prototype.html`이 소유자가 승인한 시각 기준이다. 프로토타입에 없는 화면 구성 변화가 필요해지면 — 코드를 짜지 말고 **HTML로 제안을 만들어 멈추고 소유자 승인을 기다린다.** 통합 후에도 HTML 리뷰 팩으로 최종 승인을 받은 뒤에만 메인에 병합한다
4. **Figma 배선 전제.** 소유자가 Figma에서 모든 버튼의 목적지를 배선한다. 코드의 내비게이션은 이 문서 §6 배선표와 1:1로 일치해야 하며, 배선표에 없는 화면 전환을 만들면 안 된다 (필요하면 배선표 수정 제안 먼저)

**모델 배정:** R0·R4 = Fable | R1·R2·R3 = Sonnet (막히면 Fable 승격)

```markdown
- 프로토타입에 없는 화면·구성이 필요해지면: 구현하지 말고
  review/proposals/<화면명>.html로 제안을 만든 뒤 멈추고 보고한다.

  전환 추가 금지 (필요 시 배선표 수정을 먼저 제안).
```

## 7. 내비게이션 맵 — `docs/navigation-map.md`로 저장할 배선표

이 표가 **코드 내비게이션과 Figma 프로토타이핑 배선의 공동 기준**이다. R0가 이 섹션을 그대로 `docs/navigation-map.md`로 저장한다. Figma에서 커넥션을 걸 때 이 표를 체크리스트로 쓴다.

### 7-1. 클립/온보딩 레인 (프로토타입 승인분)

| # | 화면 ID | 트리거 (버튼·제스처) | 목적지 | 비고 |
|---|---|---|---|---|
| 1 | `clip` 카드 수신 | 「내 카드 만들기」 | `interests` | |
| 1 | `clip` | 「카드는 어떻게 만들어지나요?」 | 설명 시트 → 닫으면 `clip` | 시트는 Figma 오버레이로 |
| 2 | `interests` 관심사 | 칩 탭 (토글, 최대 5) | 자기 화면 (프리뷰 갱신) | 0개면 다음 비활성 |
| 2 | `interests` | 「다음 · n/5」 | `vibe` | |
| 2 | `interests` | 뒤로 스와이프 | `clip` | 시스템 제스처 |
| 3 | `vibe` 성향 | 카드 4택1 | 자기 화면 (선택 표시) | 미선택이면 다음 비활성 |
| 3 | `vibe` | 「다음」 | `intro` | |
| 4 | `intro` 입력 | 이모지 탭 (토글) | 자기 화면 (프리뷰 갱신) | 선택사항 |
| 4 | `intro` | 「카드 완성」 | `card` | 입력 전부 비워도 진행 |
| 5 | `card` 내 카드 | 「맞대기」 | `bump` | |
| 6 | `bump` 맞대기 | 근접 감지 (프로토: 버튼) | 애니메이션 1.5s → `overlap` | 실앱: MPC 자동 트리거 |
| 7 | `overlap` 겹 결과 | 「카드 받기」 | `keep` | 겹침 0개 변형 있음 |
| 8 | `keep` 보관·전환 | 「전체 앱 받기」 | SKOverlay(App Store) → 완료 시 `done` | **이 화면 이전에 설치 유도 금지** |
| 8 | `keep` | 「나중에 할게요」 | `done` | 거절 비용 0 |
| 9 | `done` 컬렉션 | (프로토: 「처음부터」= `clip`) | 실앱: 홈 탭 유지 | |

### 7-2. 화면 상태 변형 (Figma에서 변형 프레임으로 그릴 것)

| 화면 | 변형 | 조건 |
|---|---|---|
| `interests` | 다음 버튼 비활성 | 선택 0개 |
| `intro` | 이모지 선택됨/안 됨 | 토글 |
| `overlap` | 겹침 0개 — "겹치는 관심사는 없지만" | 교집합 없음 |
| `keep` | 겹친 개수 표기 변화 | 교집합 수 |
| `done` | 빈 컬렉션 (점선 슬롯 + "다음 만남이 여기에") | 겹 0건 |

### 7-3. 실앱 전용 화면 — 프로토타입에 없음, Figma에서 추가로 그릴 것

| 화면 | 내용 | 연결 |
|---|---|---|
| 로컬 네트워크 권한 요청 | 시스템 얼럿 전 사전 설명 1장 | `card`→`bump` 사이 최초 1회 |
| 교환 실패 | 재시도/취소 (실패 사유 1줄) | `bump`에서 타임아웃 시 |
| 본앱 홈 | 내 카드 + 컬렉션 진입 (탭 구조 확정 필요) | 풀앱 시작점 |
| 설정 | 프로필 수정·계정 삭제 | 홈에서 |
| 클립→풀앱 첫 실행 | 마이그레이션 완료 안내 | 풀앱 최초 실행 시 |

※ 이 5장은 **구성만 새것이고 시각은 기존 컴포넌트로** — 가드레일 적용. 구성안이 필요하면 R4 이전에 HTML 제안(`review/proposals/`)으로 먼저.

## 8. 실행 순서 요약

```
R0 (동기화+감사, Fable) → 보고 확인
   ↓
R1 ∥ R2 ∥ R3 (Sonnet 병렬)
   ↓
R4 (통합, Fable) → review/realign-review.html 생성 → ⏸ 소유자 HTML 검토
   ↓ 승인
메인 병합 → 실기기 확인 → [Figma 상세 디자인과 합류] → TestFlight 트랙
```

당신(소유자)의 개입 지점은 두 곳: **R0 감사 보고 확인**(세션 수 확정)과 **R4 리뷰 팩 승인**(HTML 게이트). 나머지는 허용 세션으로 자율 진행된다.
