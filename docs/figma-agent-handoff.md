# 겹(Gyeop) — Figma 리디자인 에이전트 인수인계

**이 문서의 용도:** 새로 여는 Figma 작업 전용 Claude Code 세션의 시작 컨텍스트. 이 세션은 Figma를 실제로 조작하며(배선·리디자인·자산 제작), 소유자는 Figma 초보이므로 에이전트가 튜터 역할을 겸한다. **이 파일 하나만 읽으면 필요한 맥락이 전부 있다** — 다른 문서는 §5의 경로로 필요할 때만.

## 1. 시작 전 소유자 준비 체크리스트 (5분)

- [ ] Figma 계정 생성 (figma.com — Google 로그인 가능)
- [ ] **Figma 데스크톱 앱** 설치 (figma.com/downloads — 브라우저보다 데스크톱 앱이 MCP 연결에 필요)
- [ ] 플랜 확인: **에이전트가 Figma를 직접 조작하려면 유료 Dev 시트 이상 필요** (Free 플랜은 MCP 사실상 불가 — 이 경우 §3의 폴백 모드로 진행하면 되니 결제 전에 폴백으로 시작해봐도 됨)
- [ ] 새 디자인 파일 하나 생성: 좌측 상단 ☰ → File → New design file. 이름: `Gyeop v0.1`
- [ ] 터미널에서 Figma 작업 세션을 열 폴더: `~/orca/Gyeop-ios` (기획 문서 docs/가 이미 있음)

## 2. Claude Code ↔ Figma 연결 (소유자가 실행)

**방법 A — 공식 플러그인 (권장, 원격):**
```bash
claude plugin install figma@claude-plugins-official
```
설치 후 Claude Code 안에서 `/plugin` → Figma → 인증(브라우저에서 Figma 로그인 승인).

**방법 B — 데스크톱 MCP (Figma 앱이 켜져 있어야 함):**
1. Figma 데스크톱 앱 → 우측 상단 계정 메뉴 → Preferences → **"Enable Dev Mode MCP Server"** 체크
2. 터미널에서:
```bash
claude mcp add --transport http figma-desktop http://127.0.0.1:3845/mcp
```

**연결 확인:** Claude Code에서 `/mcp` 입력 → figma 항목이 connected면 성공.

**시트별 권한 (중요):** Dev 시트 = **개인 Drafts 파일에만 쓰기 가능** (팀 파일은 읽기만). Full 시트 = 팀 파일 쓰기. → `Gyeop v0.1` 파일을 **Drafts에** 만들면 Dev 시트로 충분하다.

**폴백 모드 (무료 플랜/연결 실패 시):** 에이전트는 Figma를 직접 조작하지 못하는 대신, ① 임포트할 SVG를 준비해주고 ② 화면마다 "지금 Figma에서 어디를 클릭해 무엇을 할지"를 한 단계씩 안내하는 **순수 튜터 모드**로 진행한다. 결과물 품질은 같고 손이 더 갈 뿐이다.

## 5. 누적 컨텍스트 팩 (에이전트가 읽는 본문)

### 5-A. 제품 — 왜곡 없이 한 문단

처음 만난 사람과 아이폰을 맞대 정체성 카드를 교환하는 iOS 앱. 관심사 선택이 시드가 되어 카드 그라디언트가 **결정적으로** 생성된다(같은 입력=같은 카드, 이모지도 시드에 포함). 교환 순간 겹치는 관심사가 하이라이트되어 첫 대화를 연다. 받는 쪽은 설치 불필요(App Clip) — **설치 제안은 교환이 끝난 뒤에만**(제품의 핵심 주장, keep 화면 이전에 설치 유도 UI 절대 금지). 원래 아카데미 러너용이었으나 멘토 피드백으로 범용 첫 만남으로 피벗했고, 러너들은 사용자가 아니라 피드백 그룹이다. 고정 원칙: **사용자 경험이 우선 · 거절 비용 0 · 채팅/팔로우/피드 없음**.

### 5-B. 디자인 원칙과 결정 목록

**현재 승인된 시각 기준:** `docs/gyeop-prototype.html` (클릭 가능한 HTML 프로토타입). 방향 = iOS 시스템 컴포넌트 + 리퀴드 글라스 결 + **"크롬은 조용하게, 색은 카드가 낸다"** — UI는 시맨틱 컬러의 무채색 기조, 화면의 색은 카드 그라디언트가 담당. 소유자 방침: **큰 시각 이탈 없이** 내용 구성 수준의 개선만, 단 이 Figma 트랙의 결정 라운드에서 소유자가 승인한 변경은 예외.

**결정 라운드 10항목** (작업 순서 6에서 하나씩):
1. 브랜드 액센트 1색 — "겹 성립" 순간 전용 (기본값: 올리브 #66783A 계열. 참고: POSTECH Red 실험이 개발 레포 `design/postech-palette-experiment` 브랜치에 보관되어 있음 — 아카데미 정체성이라 기본 비추천이나 소유자가 볼 수 있게 언급할 것)
2. 카드 질감 — MeshGradient 제어점 수·그레인 유무·라이트/다크 동일 여부 (기본: 3×3, 그레인 약하게, 다크 동일)
3. 타이포 — SF Pro 단독 vs Pretendard 혼용 (기본: 시스템 기본)
4. 코너·간격 — (기본: 카드 20 · 버튼 캡슐 · 4pt 그리드)
5. 컴포넌트 결 — 글라스 유지 vs 플랫 (기본: 글라스)
6. 온보딩 진행 표현 (기본: 도트 3개)
7. **"겹!" 순간 연출** — 햅틱 리듬 + 모션 (기본: 더블탭 + 스케일 팝) ← 브랜드의 심장
8. 겹침 하이라이트 (기본: 색 + 0.3s 순차 페이드인)
9. 빈 상태 (기본: 점선 슬롯 + "다음 만남이 여기에")
10. **앱 아이콘 + App Clip 헤더** (기본: 겹친 두 원 로고마크 발전) ← 심사 필수

**색 체계 기준:** UI 크롬 = 시스템 시맨틱 컬러만 / 액센트 1색은 겹 순간 전용 / 카드 = 시드→HSL(채도 70~80%·명도 45~62% 고정, 흰 텍스트 대비 4.5:1 보장) / 성공·오류 = 시스템 green·red / 다크모드에서 카드는 동일.

### 5-D. 그릴 화면 목록

**반입하는 9장 (완성분):** 01 App Clip 수신 → 02 관심사(실시간 카드 프리뷰) → 03 성향 2×2 → 04 닉네임·한줄·이모지 원탭 → 05 내 카드 → 06 맞대기 → 07 겹 결과 → 08 보관·설치 제안 → 09 컬렉션. 상태 변형 5종(버튼 비활성·이모지 선택·겹침0·겹수 표기·빈 컬렉션)은 변형 프레임으로.

**새로 그릴 7장 (기존 컴포넌트 재사용, 새 비주얼 금지):**
1. 로컬 네트워크 권한 사전 설명 (card→bump 사이 최초 1회)
2. 교환 실패 — 재시도/취소
3. 본앱 홈 (탭 구조는 여기서 소유자와 확정)
4. 설정 — 프로필 수정·계정 삭제
5. 클립→풀앱 마이그레이션 완료 안내
6. SIWA 로그인 게이트 — **풀앱 전용, 클립 레인 금지**
7. 받은 카드 상세 (컬렉션→탭→상세)

### 5-E. 배선·자산 현황

- **배선표(단일 진실 원천):** 개발 레포 `docs/navigation-map.md` — 모든 버튼→목적지가 표로 있음. Figma 커넥션은 이 표와 1:1
- **이미 존재하는 자산:** `docs/assets/appclip-header.png`(개선 대상), `docs/screenshots/` 6.9″ 10장(구기획 화면 — 참고용, 재촬영 예정), 이모지 세트 `docs/assets/emoji-icons.csv`
- **개발과의 접점:** 이 트랙의 산출물은 ① `docs/design-decisions.md`(확정 토큰·결정 기록) ② 심사 자산 3종. 코드 반영은 별도 D2 세션이 **DesignSystem 토큰 파일만** 수정하는 경로로 — Figma 에이전트가 앱 코드를 직접 수정하지 않는다
- **병행 주의:** 개발 쪽에서 R1~R4 정렬 스프린트가 도는 중. Figma 트랙은 독립적으로 진행하되, 화면 구성이 배선표와 달라져야 한다는 판단이 들면 임의 변경 대신 소유자에게 배선표 수정을 제안할 것
