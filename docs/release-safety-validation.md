# 출시 전 카드 안전 기능 검증

## 준비한 범위

- 카드 생성·수정과 수신 JSON 경계, 기존 컬렉션 표시에 공통 텍스트·이모지 검사를 적용했다. 필터는 명백한 금지 표현을 검사하는 기본 방어이며 모든 유해 문맥을 판별하지 않는다.
- 차단한 전체 로컬 사용자 ID와 표시 이름은 `Application Support/Gyeop/blocked-users.json`에 원자적으로 저장한다. 쓰기 실패를 차단 성공으로 표시하지 않는다.
- 차단 시 이 소유자의 모든 카드·겹 기록을 이 기기에서 지우고 표시를 중단한다. 차단 해제 전에 남은 과거 기록도 정리해 해제로 과거 기록이 다시 나타나지 않게 한다.
- 카드 상세의 관리 메뉴 또는 컬렉션 길게 누르기 메뉴에서 신고·차단할 수 있다. 설정에서 차단 목록과 해제를 제공한다.
- 신고 화면은 사유, 수신 주소, 카드 닉네임·현재 상태·로컬 소유자 ID와 전송 내용 미리보기를 보여 준다. 메일 앱을 여는 것만 수행하며 사용자가 직접 전송해야 접수된다. 취소나 메일 앱 부재를 신고 완료로 표시하지 않는다. 로그인 토큰·Apple 사용자 식별자는 신고 내용에 포함하지 않는다.
- `ExchangeView`는 저장/검사 결과가 승인됐을 때만 겹 성립 연출로 진입한다.

## 버전 7 근접 교환 호환성

카드를 보내기 전에 상대의 전체 로컬 소유자 ID를 발견 정보와 초대 컨텍스트로 확인한다. 두 값이 일치하고 로컬 차단 대상이 아닐 때만 연결·전송을 승인한다. 받은 카드의 소유자 ID도 같은 전체 값과 일치해야 한다. 접미사 8글자나 닉네임으로 차단을 판정하지 않는다.

이 정보가 없는 이전 프로토콜 피어는 거절한다. 따라서 새 빌드와 기존 빌드 6 사이의 카드 교환은 지원하지 않는다. 양쪽 모두 새 빌드로 업데이트해야 한다. 프로토콜 번호 `7`은 앱의 Apple 빌드 번호와 별개의 교환 규약 번호다.

근처에 광고되는 정보에는 전체 앱 로컬 소유자 ID와 프로토콜 버전이 포함된다. 카드는 승인 후 암호화된 MCSession에서 전송한다. 발견 정보 자체가 암호화된 카드 전송이라는 뜻은 아니다.

로컬 ID는 피어가 제시하는 값으로 암호학적으로 인증된 신원이 아니다. 재설치 또는 수정된 앱으로 다른 ID를 제시하는 사람을 서비스 전체에서 차단하는 기능은 제공하지 않는다. 차단은 이 기기의 해당 로컬 ID에 적용되며, 상대 기기에 이미 전달된 내 카드를 원격으로 삭제하지 못한다.

App Clip은 이번 출시 대상에서 제외되어 있으며 기존 소스는 변경하지 않는다. 다시 활성화하려면 전체 소유자 ID를 받는 새 교환 API 전환과 신고·차단을 포함한 별도 안전성 검증이 필요하다.

## 자동화 검증 상태

주요 새 정책·저장소·피어 신원·신고·UI 테스트는 구현 전에 작성했고, 기존 삭제 테스트는 연동 변경과 함께 보강했다. 현재 Windows에는 `swift`·`xcodebuild`가 없어 RED/GREEN 실행, 네이티브 컴파일, 테스트 성공이나 커버리지를 확인하지 못했다. 정적 검사와 `git diff --check`는 통과했다. 2026-11-20 사용자 지시에 따라 네이티브 검증 전 GitHub 작업 브랜치로 공유하며, Mac 시작 절차는 `release-mac-handoff.md`에 기록한다.

Mac 프로젝트 루트에서 실행한다.

```bash
xcodegen generate
swift test --package-path Packages/GyeopPackages
xcodebuild -project Gyeop.xcodeproj -scheme Gyeop \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' \
  -only-testing:GyeopUITests/ReleasePrivacyUITests \
  -only-testing:GyeopUITests/ReleaseSafetyUITests test
xcodebuild -project Gyeop.xcodeproj -scheme Gyeop \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' test
```

주요 회귀 테스트: `ContentModerationPolicyTests`, `BlockedUserStoreTests`, `PeerIdentityTests`, `CardPayloadTests`, `CardReportDraftTests`, `AccountDeletionServiceTests`, `ReleaseSafetyUITests`.

## 실기기 2대에서 반드시 확인

1. 두 기기를 모두 새 빌드로 업데이트하고 정상 교환·동시 초대·재시도·한쪽 먼저 완료를 확인한다. 상대 광고 종료가 먼저 와도 이미 승인된 연결의 수신 완료가 실패하지 않아야 한다.
2. 한 기기에서 상대를 차단한다. 닉네임만 바꾼 같은 소유자가 다시 시도해도 차단한 기기의 카드가 먼저 전송되거나 상대 카드가 표시되지 않아야 한다.
3. 앱 강제 종료·재실행 후에도 차단이 유지되어야 한다. 전체 ID가 다른 두 사람이 마지막 8글자만 같더라도 잘못 차단하지 않아야 한다.
4. 차단 해제 후 새 교환은 가능해야 하며, 삭제된 과거 기록은 복원하지 않아야 한다.
5. 기존 빌드 6 상대와의 연결은 카드 전송 전에 거절되어야 한다. 두 기기 업데이트 후 정상 교환되는지도 확인한다.
6. 카드 내용 필터에 걸리는 새 입력·수정·수신·기존 기록이 화면이나 성공 연출에 노출되지 않는지 확인한다. 필터에 걸린 내 기존 카드는 수정 경로가 보여야 한다.
7. 카드 신고의 미리보기와 실제 메일 초안이 일치하는지 확인한다. 메일 전송 취소 및 메일 앱 미설정 시 신고 접수 완료라는 표시가 없어야 한다.
8. 저장소 쓰기 실패 시 차단 성공으로 표시하지 않는지, 이미 차단 저장에 성공했지만 기록 정리에 실패했다면 목록에 차단이 유지되는지 확인한다.
9. 계정 삭제 후 SwiftData·이전/새 Apple Keychain 세션·차단 파일이 모두 정리되는지 확인한다.

신고 처리자는 지원 이메일을 확인하고 문제를 조사·응대해야 한다. 이 로컬 기능만으로 Apple 심사 승인이나 전체 사용자 대상의 제재를 보장하지 않는다.
