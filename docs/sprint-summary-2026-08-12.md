## 2. 결정 라운드 흐름 (소유자 피드백 → 반영)

1. **F54~F60** 요청서 6개 항목 + 시안 3회 왕복 → 모델 교체·유리 카드·MBTI 화면·개명·시트 블러·겹 결과 담백화
2. **F61** 목업 3장 + 그라디언트 레퍼런스 → 4색 코너 오라, MBTI 3컬럼 레드, 홈 플립 직결
3. **F62** CTA 위계 → 「다음」 전폭 통일(카드 완성 버튼과 동일), 홈 카드 +20%, 선택 스프링
4. **F63** 이모지 칸 애플 레퍼런스 선택 → 연락처 포스터 방식(시스템 이모지 키보드)
5. **F64** 완료 버튼 오류 → 자동 닫힘(메시지 반응 픽커 문법), 칩 -20%
6. **F65** 마무리 → CTA 블러 바, 긴 이름 제외, 홈 헤더 정렬, 받은 카드 삭제, 유리 MBTI 글자
7. **F66** 재결정 → 칩 이모지 복귀 + 4글자 이상 이름 선택지 제외
8. **F67~F71** 실기기 피드백 → 하단 페이드, SIWA 모드 전환·규정, 알약 깜빡임, 페이드 높이, **바닥 뜸·받은 카드 과대 (F71)**

## 3. 버그 수정 — 원인과 교훈 (아티클 척추)

이번 스프린트에서 잡은 버그는 전부 **SwiftUI 레이아웃·아이덴티티의 오해**에서 왔다.
증상이 아니라 원인을 남긴다.

### F68 — MBTI 알약 깜빡임: 뷰 아이덴티티 리셋

- **증상:** 알약을 눌러 전환하면 같은 축 반대쪽 버튼이 깜빡였다.
- **원인:** 선택 여부로 `glassProminent ↔ glass` **다른 버튼 스타일을 if/else로 교체**.
  구조 분기가 갈리면 SwiftUI는 다른 뷰로 보고 아이덴티티를 리셋한다 → 애니메이션이 아니라 재생성 플래시.
- **해결:** 한 버튼이 **같은 유리의 틴트 값만** 바꾸도록 (F69에서 `glassEffect(.regular.tint())`).
- **규칙:** 상태 전환은 *구조 교체*가 아니라 *속성 변화*여야 한다. (F46 "컨테이너 애니메이션 금지"와 같은 계열)

### F67 — SIWA 버튼이 다크 모드로 전환되지 않음

- **원인:** `SignInWithAppleButton`은 **생성 시점에 스타일이 고정**된다. `colorScheme`이 바뀌어도 이미 만들어진 버튼은 그대로.
- **해결:** `.id(colorScheme)`으로 모드 변경 시 재생성. (아이덴티티를 *일부러* 리셋하는 반대 사례 — F68과 짝을 이룬다)
- **덤:** 공식 에셋 규정상 시스템 버튼을 `clipShape`로 자르면 안 된다 → 캡슐 클립 제거.

### F70·F71 — 하단 페이드가 "바"로 보이고, 바닥이 뜸

- **F70 원인:** 페이드 그라디언트가 `safeAreaInset` 콘텐츠 높이(약 80pt) 안에서만 그려져 투명→불투명이 너무 빨리 끝났다 → 경계선이 보임.
- **F71 원인:** `.frame(height:)` **뒤의** `.ignoresSafeArea()`는 확정된 크기를 *옮길 뿐 늘리지 못한다.* 페이드가 홈 인디케이터 구간 위에 떠서 화면 맨 아래에 콘텐츠가 비치는 띠가 남았다.
- **해결:** 높이를 220pt로 키우고, 음수 하단 패딩(-60)으로 **그리는 영역만** 컨테이너 아래로 내린다(배경은 클리핑되지 않는다).

### F71 — 받은 카드가 화면을 가득 채움

- **원인:** `GridItem(.adaptive(minimum: 180))`. 393pt 기기에서 가용 폭은 361pt인데 두 칸은 180×2+8=**368pt**로 넘친다 → 적응형 그리드가 **1열로 무너지고**, 그 1열이 전폭으로 늘어나 카드 높이가 515pt가 됐다.
- **해결:** 열 수를 **고정**(2열 `.flexible()`)해 폭이 기기에서 계산되게.
- **규칙:** `.adaptive(minimum:)`은 "최소 폭"이 아니라 "열 수를 정하는 임계값"이다. 임계값이 가용 폭의 절반을 넘으면 조용히 1열이 된다.

### F49 (이전 스프린트, 참고) — 매 프레임 재계산

`KeyframeAnimator` 콘텐츠 클로저 안에서 sha256 + 대비 보정 루프가 매 프레임 돌던 사고. 이번 스프린트의 오라 개정에서도 같은 원칙(색 계산은 `init`에서 한 번)을 유지했다.

## 4. 아티클 소재 (측정·근거가 이미 코드/문서에 있는 것만)

1. **결정론적 정체성 카드** — 같은 입력 = 같은 카드. sha256 시드 → SplitMix64 → MeshGradient 25점. `ownerID`를 시드에서 뺀 이유(온보딩 실시간 프리뷰와 저장본이 픽셀 동일해야 한다). 근거: `CardKitTests` 결정성 테스트.
2. **파스텔에서 대비를 지키는 수학** — 흰 텍스트 4.5:1 보정(명도를 깎는다) → 오라 파스텔에서 **보정 방향 반전**(잉크 기준, 명도를 올리고 모자라면 채도를 뺀다, 천장 0.97). WCAG 상대 휘도를 HSB 위에서 계산. 근거: 100개 시드 전수 대비 테스트.
3. **원형 색상환에서의 그라디언트 보간** — hue를 선형 보간하면 빨강↔보라 사이에서 무지개를 돈다. `atan2` 벡터 합 원형 보간 + 인접 hue 스윕(0.08~0.15)으로 레퍼런스의 "큰 면이 흐르는" 오라를 만든 과정.
4. **SwiftUI 아이덴티티 3부작** — F68(구조 교체가 깜빡임을 만든다) · F67(일부러 리셋해야 하는 경우) · F46(컨테이너 애니메이션이 하위 전체를 흔든다). 한 편으로 묶기 좋은 세 사례.
5. **레이아웃이 조용히 무너지는 법** — F71 `.adaptive(minimum:)` 1열 붕괴 + `.frame` 뒤 `.ignoresSafeArea`가 크기를 늘리지 못하는 문제. "에러 없이 잘못 그려지는" 버그의 전형.
6. **SwiftUI에 없는 API를 최소 침습으로 감싸기** — `keyboardType`에 이모지가 없다. `UITextInputMode` 오버라이드만 UIKit으로 래핑(F63)하고 나머지는 SwiftUI에 둔 경계 설계.
7. **디자인 왕복을 코드로 굳히는 프로세스** — 소유자 피드백을 F-번호로 축적해 docs를 단일 진실로 삼는 방식. 같은 주제가 5번 뒤집힌 기록(F21→F24→F25→F56→F61)이 그대로 남아 추적 가능하다.
8. **스크린샷을 CI 산출물로** — XCUITest 풀 플로우 + xcresult attachment 추출로 라이트·다크·Dynamic Type 화면 인벤토리 자동 생성.

## 5. 남은 일 (다음 담당자에게)

**제출 전 필수** (자세한 근거는 `docs/codex-handoff.md` §1)

1. 본앱 `App/Support/Gyeop.entitlements`의 `PLACEHOLDER.gyeop.example` associated-domains 2줄 제거
2. 실기기 2대 맞대기 시연 영상 촬영 → 리뷰 노트 첨부
3. 개인정보 처리방침 공개 URL 게시 + 문의처 팀 주소로 교체
4. 연령 등급 재검토(4+ → 12+ 여부), 리뷰 노트에 "1:1 근접 교환·공개 노출 없음" 명시

**기능 백로그**

- 카드 상세에서도 받은 카드 삭제 노출 (현재는 홈 길게 누르기만)
- SIWA 요청 스코프 축소(`[]`) — 이름·이메일을 쓰지 않는다
- 실기기 체감 튜닝 대상 상수: `Glass`(카드 마감·MBTI 글자), `MBTIStepView.Layout`(bloom), `HapticTuning`, `DS.Opacity.shimmer`

**작업 규칙**: `docs/codex-handoff.md` §3의 프롬프트를 다음 세션 시작에 그대로 넣으면 된다.
